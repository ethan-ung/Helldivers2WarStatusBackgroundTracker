# Helldivers 2 War Status Background Tracker

Renders the galactic war as your Windows desktop wallpaper, refreshed every five
minutes from the [community Helldivers 2 API](https://github.com/helldivers-2/api).

A vertical panel on the right of each monitor shows the four busiest planets with
their ownership, liberation or defence progress, and rate of change, alongside
the current Major Order and the latest High Command dispatch. Behind it sits a
backdrop themed to the biome of the planet with the most Helldivers on it.

## What it shows

- **Top 4 planets by player count**, drawn from the active campaigns.
- **Ownership tag** in the owning faction's colour: Super Earth blue, Terminids
  yellow, Automatons red, Illuminate purple.
- **Progress bars.** Liberation and Super Earth defence progress are always blue.
  When a campaign is on a timer, a second bar in the opposing faction's colour
  tracks how much of the window has burned.
- **Rates** in percent per hour for both bars.
- **Major Order** objectives as tick boxes, with a count on counter objectives.
- **Latest High Command dispatch**, with the game's markup stripped.

### The three campaign states

| State | Condition | Blue bar | Second bar |
|---|---|---|---|
| Liberation | no event | liberation % | — |
| Timed liberation | event, initiator `Humans` | event % | window elapsed, in the holder's colour |
| Defence | event, initiator not `Humans` | defence % | window elapsed, in the invader's colour |

## Requirements

- Windows 10/11
- Python 3.11+ with [Pillow](https://pypi.org/project/Pillow/)

No other dependencies - HTTP goes through the standard library.

```bash
pip install Pillow
```

## Usage

```bash
python run_once.py --dry-run
```

Fetches live data and prints the resolved state without drawing anything.

```bash
python run_once.py --preview
```

Renders one image per monitor into a temp folder and opens it. Does not touch
your desktop.

```bash
python run_once.py --once
```

Full cycle: fetch, render, set the wallpaper.

```bash
python run_once.py --restore
```

Puts back the wallpaper that was in place before the first run.

### Running it every five minutes

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install_task.ps1
```

Registers a `Helldivers2Wallpaper` scheduled task running `pythonw.exe` (no
console flash), repeating every five minutes and again at logon. If a task of
that name already exists it is replaced.

```powershell
powershell -ExecutionPolicy Bypass -File scripts\uninstall_task.ps1
```

Removes the task and restores the original wallpaper. Pass `-KeepWallpaper` to
leave the current image alone.

## Custom biome art

The API supplies biome names and imagery for planetary biomes. To use your own screenshots instead, drop images into `assets/biomes/` named
after the biome:

```
assets/biomes/Desert Dunes.jpg
assets/biomes/Icy Glaciers.png
```

Matching ignores case, spaces, underscores and hyphens, and accepts the common
naming variants listed in `BIOME_FILE_ALIASES` (so `Autumn Forest.png` resolves
to `Deciduous Autumn Forest`, and `Magma Desert.png` to `Magma`). Anything you
supply is scaled to cover the monitor and centre-cropped. The 25 biome names in
the live galaxy are the keys of `PALETTES` in `hd2tracker/biomes.py`.

Any biome without an image falls back to art generated by pillow, so a partial set is
fine.

Drop a `.ttf` into `assets/fonts/` to override the display typeface.

## Configuration

Everything tunable lives in `hd2tracker/config.py`:

| Setting | Default | Purpose |
|---|---|---|
| `PLANET_COUNT` | 4 | planets shown |
| `DISPATCH_REFRESH_MINUTES` | 15 | how often the dispatch feed is refetched |
| `DISPATCH_BODY_LINES` | 4 | wrapped lines of dispatch body shown |
| `HISTORY_WINDOW_MINUTES` | 90 | window for the rate fit |
| `RATE_MIN_SPAN_MINUTES` | 10 | minimum history before a rate is shown |
| `BACKGROUND_HYSTERESIS` | `True` | stops the backdrop flip-flopping between two close planets |
| `ORDER_HYSTERESIS` | `False` | set `True` to stabilise card order too |
| `STALE_AFTER_MINUTES` | 20 | when a cached render gets a STALE marker |

Set `HD2_STATE_DIR` to relocate state.

### Identifying yourself to the API

The API asks clients to identify themselves through `X-Super-Client` and
`X-Super-Contact`, so its maintainers can reach whoever is running a client that misbehaves. Anything reachable works — an email address, a GitHub handle, a repository URL.

So no personal address ends up in version control, the contact is resolved at runtime in this order:

1. the `HD2_API_CONTACT` environment variable
2. `contact.local` in the repository root, which is git-ignored
3. a neutral placeholder

To set it, copy the example and edit it:

```bash
cp contact.local.example contact.local
```

Put your contact on the first non-comment line. With neither the file nor the variable set the tracker still runs and still sends the header, just with a placeholder instead of a way to reach you.

## How it behaves

- **Two API requests per cycle** (2 requests every 5 minutes) against a 5-request/10-second limit. The planet
  name list is fetched at most weekly, and only when a Major Order is active.
- **The dispatch feed is fetched on its own 15-minute throttle**, cached to disk
  in between. It returns every dispatch ever published as a single 372 KB
  response and ignores `limit`/`page`/`count`, while new dispatches appear only
  two or three times a day — so polling it every cycle would be wasteful. All
  requests ask for gzip, which roughly halves it.
- **The panel respects the work area**, so it stops above the taskbar. The
  wallpaper image is still the full monitor size and sits behind it.
- **Rates need warm-up.** Expect `—` for the first 10-15 minutes; that is
  deliberate, rather than showing a fabricated `0.00`.
- **The clock comes from the HTTP `Date` header.** The `now` field on
  `/api/v1/war` reports a 1972 timestamp and is unusable.
- **Failures leave your desktop alone.** If the API is unreachable the last good
  snapshot is re-rendered with a STALE marker; if there is no snapshot yet,
  nothing is changed.
- **Output filenames alternate** between `_a` and `_b` per monitor, because
  Windows caches wallpapers by path and would otherwise not repaint.

## State

Written to `.state/` inside the repo, which is git-ignored:

| File | Contents |
|---|---|
| `hd2_mon{n}_{a,b}.png` | rendered wallpapers |
| `history.json` | rolling samples for the rate fit |
| `last_snapshot.json` | last good state, for the stale fallback |
| `dispatch.json` | latest dispatch and when it was fetched |
| `wallpaper_backup.json` | your original wallpaper, captured once |
| `biome_cache/` | generated backdrops |
| `tracker.log` | rotating log |

Keeping state in the repo makes the project self-contained, and because git does
not touch ignored files it survives branch switches. Two things follow from it:

- **`git clean -xdf` will delete `wallpaper_backup.json`**, which is the only
  record of the wallpaper you had before setting this up. Copy it somewhere else
  if that matters to you.
- Moving or re-cloning the repo changes the wallpaper paths. Run
  `python run_once.py --once` afterwards to repoint them.

Set `HD2_STATE_DIR` to put state elsewhere.
